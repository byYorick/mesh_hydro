# Переосмысление UI добавления теплицы

## 1. Текущее состояние

### 1.1 Поток настройки новых узлов
- Представлен страницей `src/views/Setup.vue`, использующей стор `useSetupStore`.
- Источник данных — REST-эндпойнты `/new-nodes`, `/new-nodes/:mac`, `/new-nodes/:mac/configure`.
- Состояние хранит список обнаруженных устройств (`newNodes`), историю событий (`history`), флаги загрузки и активный MAC при конфигурации.
- Диалог `src/components/setup/SetupWizardDialog.vue` работает для любого узла:
  - **Шаг 1** — инструкции по подключению к Wi-Fi устройства.
  - **Шаг 2** — мониторинг статуса (root: подключение, прочие: метаданные).
  - **Шаг 3** — ввод параметров (`nodeId`, `zone`, `meshId`, для root ещё Wi-Fi/MQTT).
  - **Шаг 4** — подтверждение (только для root).
- Зона указывается вручную через `v-combobox`; список формируется из названий зон (`zonesStore.zones`). Привязки к теплице нет.
- После отправки формы стор вызывает `api.configureNewNode`, обновляет историю и удаляет узел при событии `handleConfigured`.

### 1.2 Управление зонами
- Стор `src/stores/zones.ts` оперирует сущностью **Zone** (id, `mesh_network_id`, `root_node_id`, `zone_type`, параметры ёмкости, связанный `current_cycle_id`).
- Источники данных — REST `/api/zones`, `/api/zones/:id`, `/api/zones/:id/nodes`, `/api/zones/:id/statistics`.
- Выбор активной зоны хранится в `localStorage`.
- Диалог `src/components/zones/AddZoneDialog.vue` создает новую зону:
  - Поля: название, описание, расположение, тип системы, root-node (из `nodesStore.nodes`), mesh ID, MQTT префикс, параметры ёмкости и флаги статуса.
  - Выбор root-node возможен только среди узлов типа `root`, не привязанных к зонам.
- Зоной управляют отдельные виджеты (`ZoneDashboard`, `ZoneCard`), но нет агрегирующего контекста теплицы или привязки к физическому объекту.

### 1.3 Циклы роста
- Стор `src/stores/growth.ts` описывает культуры, пресеты и циклы (`GrowthCycle`), работает через API `/api/growth/*`.
- Цикл связан только с `zone_id`. Для активного цикла контролируются стадии, параметры и история.
- UI (страницы `GrowthPlanner.vue`, `CycleDetail.vue`, компоненты `CreateCycleDialog.vue`, `ZoneSelector.vue`) предполагает, что пользователь заранее знает зону, с которой работает цикл.
- Уровня теплицы или набора зон в контексте цикла нет; пользователь выбирает зону вручную из выпадающего списка.

### 1.4 Узлы и телеметрия
- Стор `src/stores/nodes.ts` хранит список всех узлов (`/nodes`), подкачивает состояние из `zonesApi` при фильтрации по зоне.
- Статусы узлов рассчитывает `NodeStatusManager`.
- Нет сгруппированного представления узлов по теплицам; фильтрация либо по типу, либо по текущей зоне.

## 2. Основные ограничения текущей архитектуры
- **Отсутствие сущности теплицы**: все операции основаны на зонах; невозможно визуально представить структуру комплекса.
- **Раздельные мастера**: настройка узла (`SetupWizard`) и создание зоны (`AddZoneDialog`) не связаны, поэтому оператор вручную переносит данные о mesh ID, root node и зоне.
- **Локальные справочники**: `SetupWizard` использует строковые значения зон, которые трудно валидировать/нормализовать.
- **Запуск циклов без контекста**: пользователь должен помнить, какие зоны принадлежат какой теплице и какой root-узел их обслуживает.
- **Нет общей карты**: UI не предлагает схему размещения узлов/зон, сложно оценить статус всей теплицы целиком.

Эти выводы используются как отправная точка для проектирования новой архитектуры и UX добавления теплицы.

## 3. Новая архитектура теплиц

### 3.1 Доменная модель
- `Greenhouse` — сущность верхнего уровня (`id`, `name`, `code`, `status`, `timezone`, `mesh_group`, счётчики зон/узлов/циклов).
- `GreenhouseZoneLink` — связь теплицы и зоны (`zone_id`, `zone_name`, признаки активности и занятости).
- `GreenhouseNodeLink` — связь узлов (`node_id`, `is_root`, `zone_id`, `online`).
- `GreenhouseAutomationRule` — заготовка под сценарии автоматизации (триггер + набор действий).
- Все типы описаны в `src/types/greenhouse.ts`, API-слой — `src/services/greenhouses-api.ts`.

### 3.2 Стор `useGreenhousesStore`
- Хранит список теплиц, выбранную теплицу, кэш деталей, списки узлов/зон/правил.
- Поддерживает выбор активной теплицы (persist в `localStorage`), синхронизирует `useSetupStore`.
- Интеграция с другими сторами:
  - `useZonesStore.updateZoneGreenhouse` — при привязке/отвязке зоны обновляет кэш зон.
  - `useNodesStore.setNodeGreenhouse` — отражает назначение узлов.
  - `useGrowthStore.createCycle` — позволяет запускать цикл с `greenhouse_id`.

### 3.3 Модификации существующих сто́ров
- `useZonesStore`: новые поля `greenhouse_id`, `greenhouse_name`, геттер `zonesByGreenhouse`, экшен `getZonesByGreenhouse`.
- `useNodesStore`: поля `greenhouse_id`, `greenhouse_name`, геттер `nodesByGreenhouse`, экшен `setNodeGreenhouse`.
- `useGrowthStore`: поле `greenhouse_id` в `GrowthCycle`, вычисление `cyclesByGreenhouse`, передача `greenhouse_id` в `createCycle`.
- `useSetupStore`: состояние `targetGreenhouseId`, автодобавление `greenhouse_id` в payload конфигурации, обновление данных теплицы при `handleConfigured`.
- `AddZoneDialog` и `SetupWizardDialog` позволяют выбрать теплицу из справочника.

## 4. UX и алгоритм добавления теплицы

### 4.1 Мастер `GreenhouseWizard`
1. **Описание** (`GreenhouseWizard.vue`) — ввод названия, кода, локации, статуса, профиля климата (`CreateGreenhousePayload`).
2. **Root узел** — выбор существующего ROOT из `useNodesStore`; привязка выполняется через `greenhousesStore.attachNode`.
3. **Зоны** — выбор существующих свободных зон (`zonesStore.zones`) и добавление черновых зон. Новые зоны создаются через `zonesStore.createZone` с генерацией Mesh ID/ MQTT и тут же прикрепляются к теплице (`attachZone`).
4. **Запуск цикла** — опциональный автозапуск цикла (`growthStore.createCycle`) с показом доступных пресетов и зон.

### 4.2 Диаграмма процесса

```mermaid
flowchart TD
    A[Оператор запускает мастер] --> B[Вводит базовую информацию]
    B --> C[Выбирает Root узел (опционально)]
    C --> D[Выбирает существующие зоны / добавляет новые]
    D --> E{Нужен автозапуск цикла?}
    E -- Да --> F[Выбор пресета и зоны]
    E -- Нет --> G[Пропуск шага]
    F --> H[Подтверждение]
    G --> H
    H --> I[Создание теплицы]
    I --> J[Привязка Root узла]
    J --> K[Привязка существующих зон]
    K --> L[Создание черновых зон]
    L --> M[Привязка новых зон]
    M --> N{Автозапуск выбран?}
    N -- Да --> O[Создание Growth цикла]
    N -- Нет --> P[Пропустить]
    O --> Q[Обновление сто́ров и выбор теплицы]
    P --> Q
    Q --> R[Теплица готова к настройке узлов]
```

### 4.3 Пользовательский интерфейс
- `src/views/Greenhouses.vue` — список теплиц, карточка выбранной теплицы, зоны, узлы и активные циклы.
- В `Setup.vue` добавлен селектор «Целевая теплица», который синхронизирует `useSetupStore.targetGreenhouseId`.
- `SetupWizardDialog` включает выбор теплицы на этапе параметров узла; значение подставляется в payload `configureNewNode`.
- `AddZoneDialog` позволяет сразу назначить теплицу новой зоне.
